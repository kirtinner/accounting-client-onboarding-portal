# Contributing

This project is developed incrementally, with each change kept focused and reviewable.

## Development Process

- Make one logical change per commit.
- Review changed files before committing.
- Keep documentation updated when behavior, setup, architecture, or project decisions change.
- Use clear commit messages that describe the purpose of the change.
- Review all generated code before committing.

## Commit Message Guidance

Prefer concise messages in the imperative mood, for example:

```text
Add Invitation domain model
Configure Flyway migrations
Document Xero onboarding workflow
Document local PostgreSQL setup
```

Avoid mixing unrelated code, configuration, and documentation changes in the same commit.
